# API de items con FastAPI y Supabase

Esta API permite listar, buscar, consultar y agregar items. FastAPI recibe las
solicitudes HTTP y Supabase guarda los datos de forma persistente en una tabla
PostgreSQL llamada `items`.

## Archivos principales

| Archivo | Para qué sirve |
|---|---|
| `main.py` | Define las rutas de la API y protege el endpoint para agregar items. |
| `models.py` | Define los campos permitidos y valida los datos recibidos. |
| `db.py` | Conecta con Supabase y ejecuta consultas a la tabla `items`. |
| `requirements.txt` | Lista las librerías necesarias. |
| `.env` | Guarda las claves locales; no se debe subir al repositorio. |

## Preparar Supabase

En el panel de Supabase, abre **SQL Editor**, crea una consulta y ejecútala:

```sql
create table public.items (
    id bigint generated by default as identity primary key,
    nombre text not null,
    descripcion text not null default '',
    cantidad integer not null check (cantidad >= 0)
);
```

La tabla debe llamarse `items` y sus columnas deben coincidir con el modelo de
`models.py`. `id` lo genera la base de datos automáticamente.

En la configuración del proyecto de Supabase, copia la URL del proyecto y una
clave secreta para uso de servidor. Colócala en un archivo `.env` en la carpeta
del proyecto:

```dotenv
API_KEY=pega_aqui_una_clave_larga_para_proteger_el_POST
SUPABASE_URL=https://tu-proyecto.supabase.co
SUPABASE_KEY=pega_aqui_la_clave_secreta_de_servidor
```

`SUPABASE_KEY` debe ser una clave secreta de servidor (`sb_secret_...` o la
clave heredada `service_role`), no una clave para usar en el navegador. No
compartas ni subas `.env`: esa clave permite que el servidor acceda a la base de
datos. El `.gitignore` del proyecto ya excluye ese archivo.

## Instalar y ejecutar en Windows

Desde PowerShell, en la carpeta del proyecto:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn main:app --reload
```

Abre `http://127.0.0.1:8000/docs` para probar la API.

## Endpoints

| Método | Ruta | Descripción | Protección |
|---|---|---|---|
| GET | `/` | Confirma que la API está activa. | No |
| GET | `/items` | Lista items; acepta `?buscar=texto` para filtrar por nombre. | No |
| GET | `/items/{item_id}` | Devuelve un item por id (404 si no existe). | No |
| POST | `/items` | Inserta un item en Supabase. | Header `X-API-Key` |

Ejemplo del cuerpo para `POST /items`:

```json
{"nombre": "Cuaderno", "descripcion": "Tapa dura", "cantidad": 3}
```

Para el POST, envía el header `X-API-Key` con el mismo valor configurado en
`API_KEY`. En `/docs`, usa **Authorize**; en Postman, agrega el header
manualmente.

## Cómo está conectada la aplicación

1. `main.py` recibe la petición y valida el cuerpo con `ItemNuevo`.
2. Para listar, buscar o agregar, `main.py` llama a una función de `db.py`.
3. `db.py` usa `supabase.table("items")` para consultar o insertar filas.
4. Supabase devuelve los resultados y FastAPI los responde como JSON.

La base de datos administra el `id`, por eso el cliente no debe enviarlo al
crear un item.

## Cambiar el objeto del proyecto

Si el proyecto no trata sobre items, cambia los nombres de la tabla y las
columnas en Supabase, los campos de `ItemNuevo` en `models.py`, y las consultas
correspondientes en `db.py`. También puedes ajustar las rutas y los nombres
visibles en `main.py`.
